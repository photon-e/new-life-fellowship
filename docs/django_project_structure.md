## 2) Explanation of each folder

- `config/`: Project-level Django configuration (settings split by environment, root URLs, ASGI/WSGI).
- `apps/`: Domain-driven modular Django apps. Each app owns its models, views, urls, admin, services, and migrations.
- `templates/`: Server-rendered HTML templates, grouped by feature/app for maintainability.
- `static/src/`: Tailwind source styles and unbundled frontend assets.
- `static/dist/`: Built/minified CSS/JS output generated by Tailwind/PostCSS pipeline.
- `media/`: User-uploaded or generated assets served via protected media strategy.
- `frontend/`: Frontend toolchain (Tailwind, PostCSS, npm scripts).
- `tests/`: Test suites split by scope (unit, integration, e2e).
- `scripts/`: Operational scripts (ingest jobs, maintenance, deployment entrypoints).
- `docker/`: Container definitions and runtime configs (Django/Nginx/Celery).

## 3) Recommended Django apps

- `core`: Shared abstractions, utility code, base classes, permissions.
- `users`: Custom user model, auth/profile management.
- `creators`: Creator channels/profiles and ownership metadata.
- `categories`: Taxonomy and category hierarchy.
- `videos`: Video metadata, status, publishing, and catalog logic.
- `playlists`: User and editorial playlists.
- `streaming`: Playback endpoints, signed URLs/tokens, entitlement gate.
- `analytics`: Watch events, aggregates, and reporting jobs.

Optional additions as the platform grows:
- `search` (indexing and query features)
- `billing` (subscriptions/payments)
- `notifications` (email/push/in-app alerts)

## 4) Where to store video files

For local development:
- Store uploaded files under `media/videos/`.
- Thumbnails under `media/thumbnails/`.
- Subtitle files under `media/subtitles/`.

For production (recommended):
- Use object storage (e.g., AWS S3, Cloudflare R2, GCS), not local disk.
- Suggested object key layout:
  - `videos/{video_id}/source/original.mp4`
  - `videos/{video_id}/hls/master.m3u8`
  - `videos/{video_id}/hls/720p/segment_00001.ts`
  - `videos/{video_id}/thumbnails/poster.jpg`
  - `videos/{video_id}/subtitles/en.vtt`
- Serve via CDN and use signed URLs for private content.

## 5) Best practices for large Django projects

1. **Use a modular monolith first**
   - Keep a single deployable Django project with clear domain app boundaries.

2. **Split settings by environment**
   - `base.py`, `dev.py`, and `prod.py`; keep secrets in env vars.

3. **Adopt service + selector pattern**
   - Keep views thin; business logic in `services.py`; read/query logic in `selectors.py`.

4. **Use a custom user model from day one**
   - Avoid migration pain later when adding auth fields.

5. **Keep static, templates, and media separate**
   - `templates/` for HTML, `static/` for build assets, `media/` (or object storage) for uploads.

6. **Use async workers for heavy tasks**
   - Offload transcoding, thumbnail generation, and analytics processing to Celery/RQ.

7. **Version and secure media delivery**
   - Prefer HLS assets in object storage + CDN with signed URLs or tokenized access.

8. **Design for observability**
   - Structured logging, metrics, and health endpoints from the beginning.

9. **Enforce quality gates**
   - CI with tests, linting, formatting, and migration checks.

10. **Document architecture decisions**
   - Keep ADRs and domain boundaries documented to prevent app coupling.
